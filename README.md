# Альфа-Курс · Персональные рекомендации

Бэкенд для трека 1 Changellenge >> Hack&Change 2026. Он помогает предпринимателю выбрать учебный материал под текущую задачу и понять, что делать дальше.

## С чего начать команде

| Шаг | Что сделать | Как проверить |
|---|---|---|
| 1. Поднять бэкенд | Запустить демо через Docker Compose | `GET /health` возвращает `ok` и `synthetic` |
| 2. Подключить фронтенд | Загрузить варианты анкеты из `GET /api/v1/onboarding`, отправить профиль в `POST /api/v1/recommendations` | Пустая анкета и заполненный профиль показывают разные подборки |
| 3. Подключить каталог кейса | Локально импортировать `.backup`, указать `CATALOG_PATH` и перезапустить API | `GET /health` возвращает `catalog: local` |
| 4. Подготовить демонстрацию | Пройти сценарии ниже и сверить числа в презентации с выводом `python -m scripts.evaluate` | Показываются карточки, причины и следующий шаг |
| 5. Собрать сдачу | Для ZIP включить код, README и `presentation.pdf`. При сдаче через GitHub указать ссылку на первом слайде PDF | Проверяющий открывает материалы и запускает демо по инструкции |

## Запуск и проверка

```sh
docker compose up --build
```

Откройте [Swagger UI](http://localhost:8000/docs). Docker Compose слушает только loopback на порту 8000. В контейнере приложение слушает порт 8000.

1. Проверьте `GET /health`. Статус `ok`, источник `synthetic` и 15 материалов означают, что демо готово.
2. В `POST /api/v1/recommendations` отправьте `{}`. Проверьте бесплатную стартовую подборку, причины и предложение пройти короткий онбординг.
3. Отправьте профиль ниже. Первой должна идти рекомендация `m3`, подходящая по теме, стадии и формату.
4. В отдельном запросе передайте `{"stage":"growth","level":"intermediate","history":[{"material_id":"t1","event":"completed"}]}`. Ожидается `t2` на первом месте, а пройденный `t1` исключается.
5. Отправьте `{"task":"квантовая телепортация"}`. Режим `fallback` предложит уточнить задачу и покажет общую подборку.
6. Сравните результаты с `"strategy":"baseline"` в том же профиле. Для этого профиля первым у бейзлайна будет `m1`.

```json
{
  "topic": "маркетинг",
  "task": "система продвижения",
  "industry": "розница",
  "stage": "growth",
  "level": "intermediate",
  "preferred_format": "course",
  "limit": 3
}
```

## API для фронтенда

| Метод и путь | Назначение |
|---|---|
| `GET /health` | Статус, источник и размер каталога |
| `GET /api/v1/onboarding` | Темы, отрасли, стадии, опыт и форматы для необязательной анкеты |
| `POST /api/v1/recommendations` | Карточки, причины рекомендации, следующий шаг и уточнение при необходимости |
| `GET /openapi.json` | Контракт для генерации клиента |

Все поля профиля необязательны. История передаётся от старых событий к новым. Поддерживаются `view`, `started`, `completed`, `dismissed`, `clicked` и `purchased`. При одновременных запросах каждый профиль обрабатывается независимо. API работает без регистрации и серверных сессий. Состояние пользователя хранит вызывающее приложение. `material.url` может быть `null`, а `material.access` может быть `unknown`. Используйте `next_step` для карточки без ссылки и показывайте метку «Уточнить условия» для неизвестного доступа.

### Пример запроса для фронтенда

Запустите API на `http://localhost:8000`. Если фронтенд работает отдельно, например на `http://localhost:5173`, добавьте этот адрес в `CORS_ORIGINS` в файле `.env` и пересоздайте контейнер командой `docker compose up -d`.

```js
const response = await fetch("http://localhost:8000/api/v1/recommendations", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    topic: "маркетинг",
    task: "система продвижения",
    stage: "growth",
    preferred_format: "course",
    history: [],
  }),
});
if (!response.ok) {
  throw new Error(`Ошибка API (${response.status})`);
}
const { recommendations, clarification, mode } = await response.json();
```

- Для карточки покажите `material.title`, `material.format`, `material.access`, `reasons` и `next_step`. Если `material.url` заполнено, отобразите ссылку.
- В режимах `cold_start` и `fallback` показывайте `clarification` рядом с подборкой. Если массив рекомендаций пуст, предложите изменить запрос.
- Для демонстрации храните события в браузере и передавайте последние 100 в порядке от старых к новым. При интеграции с платформой берите события из её истории. Покупку и завершение обучения фиксируйте только после подтверждения от платформы.
- HTTP `422` означает, что профиль не прошёл валидацию. В ответе `detail` указаны поле и причина. При сетевой ошибке покажите сообщение и кнопку повтора.

## Архитектура и данные

FastAPI валидирует входные данные через Pydantic. Каталог загружается в память при запуске. Для каждой карточки ранжировщик сопоставляет русскоязычный запрос с названием, темами и коротким описанием, затем учитывает отрасль, стадию, опыт, формат и последние взаимодействия. Он исключает завершённые, скрытые и купленные материалы, учитывает связанные материалы и слегка снижает позиции повторяющихся форматов. Вес каждого сигнала прозрачен в `app/ranking.py`. Бейзлайн сравнивает только темы с запросом и разрешает ничьи по слабому сигналу популярности и идентификатору.

В репозитории есть только синтетический каталог. Выгрузка и результаты импорта хранятся локально в `private/`. Импортёр читает выбранные блоки PostgreSQL COPY, связывает каталог с темами, тегами и отраслями, фильтрует архивные, закрытые и черновые материалы и считает суммарное число привязок к курсам. Логи отдельных пользователей и тела уроков в нормализованный каталог не попадают. В публичном демо используются придуманные названия.

### Подключение выгрузки организаторов

Нужны Python 3.12 и `pg_restore` 17 или совместимой версии. PostgreSQL-сервер не требуется.

```sh
python -m pip install -r requirements.txt
mkdir -p private
# Положите предоставленный организаторами .backup в private/.
python -m scripts.import_catalog private/alfa_course_hackathon.backup
docker compose up --build
```

Перед последней командой создайте `.env` на основе `env.example` и установите `CATALOG_PATH=/private/catalog.json`. Файл должен быть доступен на чтение UID 10001 внутри контейнера. `GET /health` покажет `catalog: local`. Для запуска без Docker укажите `CATALOG_PATH=private/catalog.json` и выполните `python -m uvicorn app.main:app`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `API_PORT` | `8000` | Порт хоста для Compose |
| `CATALOG_PATH` | пусто | Путь к импортированному каталогу |
| `CORS_ORIGINS` | пусто | Разрешённые origin фронтенда через запятую |

Внешние API, токены и LLM не требуются. Интерактивная документация Swagger загружает ресурсы интерфейса с CDN. Для проверки без доступа к CDN вызовите API напрямую.

## Оценка качества

```sh
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m scripts.evaluate
```

На шести синтетических профилях с ручной разметкой средний NDCG@3 составил 0,984 у персонального ранжирования и 0,686 у подбора по теме. Это проверка поведения прототипа. Для независимой оценки разметьте отдельные профили из разных сегментов, исключите подгонку весов по отложенной выборке и опубликуйте метрики по каждому сегменту.

### Проверка эффекта после внедрения

- Случайно распределить пользователей с правом видеть блок рекомендаций по стабильным группам 50/50. Контроль получает подбор по теме, тест получает персональные рекомендации. Места показа и правила доступа одинаковые.
- Основная метрика — доля пользователей с покупкой в течение 14 дней от включения в эксперимент. Дополнительная — число уникальных активных дней за те же 14 дней. Отдельно отслеживать CTR блока и старт обучения.
- Привязать показ, позицию, клик, старт и подтверждённую покупку к анонимному ID, варианту и материалу. До старта задать минимальный эффект, необходимый размер выборки и критерии остановки. Сравнивать группы по первоначальному назначению, включая пользователей, которые не кликнули.
- Контролировать p95 задержки, долю пустых подборок и ошибки API. Отдельно анализировать холодный старт.

## Ограничения

Разметка стадии и опыта в реальной выгрузке неполная. Импортёр осторожно выводит эти признаки из заголовков и оставляет неизвестные значения пустыми. Многие адреса в выгрузке представлены короткими идентификаторами страниц. Когда предоставленной абсолютной HTTPS-ссылки нет, API возвращает `null`. Для платных карточек импортёр не использует тексты уроков. Реальная история конкретного пользователя поступает из фронтенда, который должен передавать только ID материалов и типы событий. Рекомендатель предназначен для прототипа с небольшим каталогом и не включает оплату или авторизацию.

## Если запуск не получился

| Симптом | Что проверить |
|---|---|
| Порт 8000 занят | Задайте `API_PORT=8001` в `.env`, пересоздайте контейнер и откройте новый порт |
| API завершился при старте | Выполните `docker compose logs api`. Проверьте путь `CATALOG_PATH`, права на чтение и валидность JSON |
| Импортёр сообщает об ошибке версии архива | Проверьте `pg_restore --version`. Используйте PostgreSQL Client 17 или совместимый клиент и передайте путь через `--pg-restore` |
| Браузер блокирует запрос | Сверьте origin фронтенда, включая схему и порт, со значением `CORS_ORIGINS` |
| Swagger не открылся | Проверьте `GET /health`. Если API доступен, отправьте запрос напрямую через браузерный фронтенд или HTTP-клиент |

Перед публикацией проверьте `git status --short`. В коммит включайте только код, документацию и синтетический каталог. Храните `.env`, закрытую выгрузку и импортированные данные локально.
